## Phase 1A：D4 —— concrete hook 的数字判定

### 问题

`_extract_concrete_elements()` 用 `\d+(?:\.\d+)?\s*%? | \d+(?:\.\d+)?\s*(?:亿|万|倍|个|家|款|台|条)`
提取数字，把**单字数字**（`1`/`2`/`5`/`9`）也收进「具象元素」集合。

### 修改

- 新增类常量 `NUMERIC_UNITS`（按长度倒序，保证最长匹配：`亿元` 不会被切成 `亿`）。
- 新增 `_is_quantified_number(number, tail)`：**把「数字长度」与「单位/语义」分开判断**，
  不是把 `\d+` 改成 `\d{2,}`。
  - 带单位/比例/金额/数量后缀 → 算（`10万` / `5亿元` / `30%` / `2.5万` / `3家` / `5000台` / `2倍`）；
  - **四位年份按裸数字记**（`2026`）——标题常写「2027 量产」不带「年」；
  - 其余裸数字（`1` / `2` / `5` / `9` / `32` / `300`）→ **不算**。
- 公司名 / 地名 / 其他元素提取**未改动**（D4.4）。

### 实测（同一份模型输出重放，`--replay` 隔离变量）

| | 旧规则元素 | 新规则元素 | 删掉 | 新增 |
|---|---|---:|---|---|
| 选题 A（9秒32 机器人百米纪录，1169 字） | 2 个 `['12','18']` | 1 个 `['18个']` | `12` `18` | `18个` |
| 选题 B（比亚迪跨界人形机器人，1534 字） | 10 个 | 8 个 | `1` `2` `10` `36` `460` | `10万元` `2个` `460万` |

**规则修改已生效、可复现。**

### ⚠️ 但验收目标**未达成**：拒绝率没有下降，反而更严

| 指标 | BEFORE（旧规则） | AFTER（新规则） |
|---|---:|---:|
| 模型候选 generated | 20 | 20 |
| 模型候选 **valid** | **0** | **0** |
| 兜底候选 generated | 22 / 25 | 19 / 19 |
| 兜底候选 valid | 0 | 0 |
| **全部候选 valid** | **0 / 42、0 / 45** | **0 / 39、0 / 39** |

原因必须说清楚：**删掉裸数字只会让闸门更严，不可能降低拒绝率。**
`_has_concrete_hook` 的判定是 `any(元素 in 标题 for 元素 in 正文元素)` ——
**元素集合越大越容易通过**。旧实现把 `1`/`2`/`460` 也算元素，是**在放水**，不是在误杀。
所以「修数字会让更多标题通过」这个预期方向是反的。

`pytest`：**634 passed**（617 + 17 条 D4 新增回归），未修改任何既有断言。

## 真正剩余的 blocker（按 reason_code 统计，这是 D4 的诊断产出）

对**全部 222 个可评估历史 run**（有 `article.md` + `titles.txt`）重算标题闸门：

```
候选过闸 = 0 的 run : 101 / 222  (45.5%)
每 run 通过候选数   : mean 1.92, median 1
每 run 正文元素数   : mean 10.0, median 5
```

在这 101 个「零通过」run 里拆解原因：

| reason_code | 涉及 run 数 | 候选条数 |
|---|---:|---:|
| **`missing_concrete_hook`** | **91**（90%） | **722** |
| `editorial_integrity` | 46（46%） | 181 |
| `discouraged_pattern:先流向谁` | 5 | 5 |
| `discouraged_pattern:改写座次` | 5 | 5 |
| `discouraged_pattern:重排利润` | 3 | 3 |

### Blocker 1：`missing_concrete_hook` 在真实数据上**几乎不可满足**

它是**字面包含**判定：标题必须原样包含正文里提取出来的某个字符串。
而提取结果又少又脏：

- 选题 A 的 1169 字正文只提出 **1 个**元素（`18个`）——即**任何不含「18个」的标题全灭**。
- 选题 B 提出 8 个，其中三个是垃圾：
  - 地名正则 `[...]{2,6}(?:省|市|县|区|...)` 把 **「二级市场」切成「二级市」**、
    把 **「无法区分」切成「市场无法区」**；
  - 公司正则 `[...]{2,}(?:公司|集团|科技|...)` 把整个短语
    **「进军人形机器人这类公司」** 当成公司名。

⇒ 标题既不可能命中垃圾串，也很少刚好复述数字，于是 90% 的零通过 run 都挂着这一条。

### Blocker 2：正文层的假阳性把**整道标题闸门**打死

`validate_title_compliance()` 调 `check_editorial_integrity(title, body_text)`，
而该函数同时返回 **`_check_body_integrity(整篇正文)`** 的结果。
于是**正文自己的机械问题会被算到每一条标题头上**。

实测（选题 B 全文）：正文命中 `_BODY_FRAGMENT_PATTERN`

```python
r"[\u4e00-\u9fffA-Za-z0-9]{2,24}、(?:为|是|在|与|和|并|但|或)"
```

命中片段是 **`是后续有没有订单、并`** —— 即正文里的 **「、并且」** 被当成了残句。
后果：该选题 **39/39 候选全部**因 `编辑一致性` 被拒。

历史影响面：**243 篇历史正文里 18 篇（7.4%）命中该正则**。

## ⚠️ 对 D2 的风险提示（新证据，直接影响能否照原计划执行）

D2 要求：全灭 → 返回 no compliant title → 交给 topic attempt loop。
按上面的数据换算：

- 单次 attempt 的标题闸门通过率 ≈ **54.5%**（1 − 45.5%）；
- 4 次 attempt 全失败的概率 ≈ `0.455⁴` ≈ **4.3%**（约每 23 天有 1 天不发）。

这个数字本身**可以接受**，但有两个前提必须先讲清：

1. **45.5% 的 attempt 会被浪费**，而其中 90% 是 `missing_concrete_hook` 这个
   *几乎不可满足* 的判定造成的 —— 不是标题真的差。
2. Blocker 2（正文假阳性）与标题质量**完全无关**，却能把整篇稿子的标题全部否掉。
   不同时处理，D2 上线后每 12 篇左右就会有 1 篇纯粹因为这个正则而报废。
