# 标题闸门修复：零阅读模板「必然胜出」的链路

日期：2026-09-16 ｜ 提交：`8aa8582` ｜ 测试：`tests/test_title_selection_regression.py`（10 例）

## 一、症状

2026-09-16 云端 17:57 发布的那篇（`pgc_id=7686069361881195343`）标题是：

> 工信部推动机器人80%：具身智能如何实测

它**不是模型写的**，是代码里硬编码的兜底模板。而项目里三处地方早就指出这个句式有问题：

| 出处 | 说了什么 |
|---|---|
| `feedback_loop_service.py:33` 注释 | 点名「XX亿：XX如何实测」是「**0 阅读但展现 300-470**」的模板，曾因误判为高 CTR 被灌回提示词做 few-shot，形成自污染 |
| 账号历史实绩 | 「基地10亿：机器人如何实测」**10 阅读**；「月之暗面等大模型1240亿：大模型如何实测」**21 阅读** |
| `docs/TITLE_STRATEGY_20260916.md` | 94 条有效作品的零阅读模式之一是「**冒号+数字堆砌**」 |

## 二、必然链（三处缺陷，缺一不可）

拉出那次 run 的 `titles.txt`（15 个候选）就能看到链路：

```
 1. 工信部推动机器人80%：具身智能如何实测      ← 硬编码兜底
 2. 工信部推动机器人80%：具身智能项目实测      ← 硬编码兜底
 3. 灵巧手产业：产业链分化，2025年谁将占据利润高地
 4. 下降80%的增速里，具身智能先回款的是哪一环
 5~13. 灵巧手产业：…（9 条，同一骨架）
```

1. `title_agent._fallback_fact_titles()` 生成的骨架就是 `{主体}{数字}：{细节}如何实测` / `项目实测`；
2. 兜底以 `fact_titles + templates` 合并，**被前置到候选最前面**；
3. `review_service.select_auto_title()` 取「**第一个**通过闸门的候选」。

→ 兜底模板必然被选中。而它之所以能通过闸门，是因为 **RULE_009 的动作词表里含 `实测`** ——
闸门的正向词表恰好替这个零阅读句式背了书。

**只修任何一处都不够。**

## 三、改动

| # | 改动 | 位置 |
|---|---|---|
| 1 | RULE_007 封住该族：`如何实测$`、`项目实测$`、`如何验证$`、`下一步看什么$`、`实测：` | `article_quality_checker._TITLE_TEMPLATE_PATTERNS` |
| 2 | 兜底骨架改为实证支持的短句式（「…真实进度看交付」/「…交付进度才是关键」），且不断言订单、营收 | `title_agent._fallback_fact_titles` |
| 3 | 兜底改为**追加**（`templates + fact_titles`），不再前置；财报锚定的兜底（`_fallback_evidence_titles`）仍前置——它锚定本文真实财报，是有意为之 | `title_agent._fallback_titles` |
| 4 | 选择仍在**通过闸门的**候选里挑，但改按 `title_click_preference` 取最优，不再取第一个 | `review_service.select_auto_title` |
| 5 | 新增模型候选**骨架塌缩** warning（只观测，不改行为） | `review_service._log_title_skeleton_collapse` |

偏好分的依据（`docs/TITLE_STRATEGY_20260916.md`）：

- 高 CTR 共性：**下判断 / 设问带前提 / 反直觉 / 短**（头部 15 条平均 20.1 字）；
- 零阅读模式：模糊主体、纯陈述、冒号+数字堆砌、抽象名词罗列、硬凑标题党；
- ⚠️ **反面证据**：命中「主体+数字+后果」四要素越多的组 CTR 越低（3 项 0.00% vs 0 项 0.86%），
  所以**不用要素数量**当排序键。

权重刻意取小（长度 ≤22 字 +2 / >28 字 −2；判断设问 +2；冒号枚举 −1；未来承诺 −1；数字 ≥4 个 −1），
**排序键不可能让不合格标题复活**。

## 四、验证：用真实候选回放

把那次 run 的候选原样喂给「闸门 + 排序」：

| | 旧逻辑 | 新逻辑 |
|---|---|---|
| 兜底模板 #1/#2 | 通过 → **被选中并发布** | **被 RULE_007 拒绝** |
| 最终选择 | 灵巧手产业：产业链分化，2025年谁将占据利润高地 | **下降80%的增速里，具身智能先回款的是哪一环** |

新选择的形态与实证高 CTR 组一致（具象主体 + 数字 + 设问 + 20 字）。

## 五、上游：候选塌缩（同日补完 `fe56b97`）

闸门与排序只能在**已生成的候选**里挑。而那次 13 个候选里 11 个是同一骨架 —— 候选本身才是上游，
而且这是**被有意制造出来的**：

| 成因 | 说明 |
|---|---|
| 提示词主动教套骨架 | `growth_ops_service._recommend_title_templates()` 返回的是**程序手工合成的填空句**（按赛道写死句型、把关键词填进槽位，**没有任何实测依据**），而提示词把它标成「**可模仿标题模版**」。这些骨架本身抽象、无主体，正是同一份提示词别处明令禁止的形态 |
| 硬规则叠加 | 「标题前 14 字必须出现具体主体」＋「输出 20 个标题」→ 模型把同一主体前缀复制 11 遍 |
| 正向样本同质 | 提示词列的 5 条高 CTR 样本里，**3 条共用同一句式**，且没有任何提醒 |

**提示词改动**：

1. 「可模仿标题模版」/「可模仿选题角度」→ 改为「句式参考（**禁止套用结构**）」。
2. 新增第 20 条：同一开头骨架最多出现 2 次，至少 8 种不同开头，并把 9-16 的真实塌缩产出当反例列出。
3. 第 21 条：允许并鼓励短标题。
4. 高 CTR 样本表加注「其中 3 条共用同一句式，**不要再写第 4 条**」。
5. 末尾新增「输出前自检」5 条（把 20 条标题的前 4-6 字横排看一遍）。

**代码兜底**（因为第 19 条早就禁止填空式模板、模型仍然照做 —— 被无视过的提示词规则必须配代码）：

- `ArticleQualityChecker.title_skeleton()`：抽取「开头骨架」。
- `agent_workflow._cap_title_skeleton_families()`：每族最多保留 3 条，**保留点击吸引力最高的**。
  实测回放：**13 条 → 6 条**（10 条同骨架里砍掉 7 条）。
  **去重不是删优** —— 每族最优的一条一定活着，不存在把冠军删掉的可能。

⚠️ **尚未经过真实模型验证**：提示词改动必须等一次真实运行。验证时**不要只看最终发出去的那条标题**，
要看 `titles.txt` 的**骨架分布**（标准：同骨架 ≤2 条、≥8 种不同开头）——
只看最终标题会被「排序层恰好挑中一条好的」骗过去，掩盖候选仍然塌缩的事实。

## 七、口径与局限

- 排序键来自**实测 CTR 分布**，但样本跨 1829 天、发布时间/选题/账号权重等混杂因素未控制，
  CTR 中位数被 44 条零阅读稀释。**只能当方向性依据，不是精确因果**。
- `平台收益` 与 `账号累计收益` 是两回事：前者是单篇归因（头条不开放，仍「待回流」），
  后者才是账号真实金额（已能采集）。别混用。
