# 标题闸门 Blocker 复盘：正文层跨层泄漏 + 具象锚点（Phase 1B）

- 日期：2026-09-17
- 范围：**只修 Blocker 2（跨层泄漏）与 Blocker 1（Concrete Hook V2）**
- 明确**不动**：D2（合规闸 all-or-nothing 的失败语义）、D1（候选池隔离）、D3、
  RULE_009、`TOUTIAO_TITLE_MAX_LENGTH`（checker 40 / agent 配置的分歧）、发布服务
- 数据来源：`cache/*.json` 里**真实跑过**的运行缓存。标题候选直接用当时落盘的
  `content.titles`，所以回放可复现、且与当时的候选池一致。**全流程不调用 LLM。**

## 0. 一句话结论

`missing_concrete_hook` 之所以近 100% 判 FAIL，**主因不在标题，而在两处归因错误**：

1. **正文的问题被算到标题头上**（跨层泄漏）。一篇正文被旧残句正则误判（真实语料
   457 篇里命中 101 篇，**全部是正常中文**），该选题**全部**候选标题一起被判死。
2. **锚点提取本身是错的**：量化值被截断（`460万台`→`460万`）、真正的公司名提不出来
   （`比亚迪` 没被识别）、垃圾串被当锚点（`二级市` / `市场无法区` /
   `进军人形机器人这类公司`）。于是「标题必须承接具象信息」这句话在大多数稿子上
   **根本无法被满足**。

修完之后（同一批 108 个真实 run）：

| 指标 | BEFORE | AFTER |
|---|---|---|
| 候选过闸 = 0 的 run | **90/108（83.3%）** | **29/108（26.9%）** |
| 正文层被误判的 run | **48/108（44.4%）** | **0/108（0%）** |
| 候选通过数 / 总候选 | 103 / 2079 | **969 / 2079** |
| 具象锚点闸 UNAVAILABLE 的 run | 0（静默当成通过） | 50/108（46.3%，**如实留痕**） |
| 全量测试 | 634 passed | **700 passed** |

> BEFORE 列的复算方式：对同一批 run 用**修改前**的判定重跑一遍 ——
> `base(长度/禁用词/财务因果) ∪ _check_title_integrity(title, body) ∪ 旧残句正则(正文) ∪ 旧具象钩子`。
> 只有「旧残句规则 + 跨层合并」与「旧具象钩子」两处不同，其余闸门完全一致，因此可直接对比。

## 1. Blocker 2：正文层的问题不许否决标题

### 1.1 病根（两处串联，缺一不可）

```python
# article_quality_checker.py（修改前）
def check_editorial_integrity(self, title, content, ...):
    title_issues = self._check_title_integrity(title, content, ...)
    body_issues  = self._check_body_integrity(content)      # ← 整篇正文
    hard_blockers = [*title_issues, *body_issues]           # ← 两层合并
    return {"issues": hard_blockers, ...}
```

```python
# title_agent.py（修改前）
if ArticleQualityChecker().check_editorial_integrity(title, body_text)["issues"]:
    return False        # ← 于是「正文自己的问题」否掉了「每一条标题」
```

单单修后者、或者单单修前者都不够：只要正文命中一次残句规则，该选题 39/39 条候选
就会一起消失，而日志只会说「编辑一致性」，指向的是标题。

### 1.2 那条残句规则本身也是错的

旧规则：

```python
_BODY_FRAGMENT_PATTERN = re.compile(
    r"[\u4e00-\u9fffA-Za-z0-9]{2,24}、(?:为|是|在|与|和|并|但|或)"
)
```

在 **457 篇去重后的真实正文**上实测：命中 **101 篇（22.10%）、114 次**。
逐条看上下文后：**全部是正常中文，精度为 0。**

误报的结构性原因不是「顿号后面能不能接词」，而是**单字连接词会命中更长的词的内部**：

| 命中 | 次数 | 真相 |
|---|---|---|
| `订单、并网、交付` | 178→多为 `并` | `并` 是「**并**网」的首字 |
| `验证进度、与主流厂商` | 8 | `、与` 是并列项连接词 |
| `在手订单规模` | 16 | `在` 是「**在**手」的首字 |
| `、是否完成客户验收` | 24 | `是` 是「**是**否」的首字 |
| `、和其他` | 32 | 并列项连接词 |

收窄为**两条结构上成立的信号**（顿号不可能引出谓语；句子不可能以连接词收尾）：

```python
_BODY_FRAGMENT_PATTERN = re.compile(
    r"、[为是](?!否)"                       # 顿号 + 系动词（排除正常的 `、是否` 并列）
    r"|(?:并且|而且|…|并|但|或|与|和|是|为|在)[ \t]*"
    r"(?:\r?\n[ \t]*\r?\n|[ \t]*\Z)"        # 以连接词收尾且无终句标点（悬空尾巴）
)
```

同一 457 篇：**只剩 2 篇命中（0.44%），2 次全部是真残句**
（`…智能机器人、为最主要的增长驱动力。`、`…提到小鹏、是因为以前那些机器人`）。
项目既有夹具 `优必选、为最主要的增长驱动力…` 依然被捕获。

> 已放弃的候选规则（噪声过大，不采用）：
> 「段落无终句标点」120/243、「。，标点错接」52/243、「悬空从句开头词」64/243、
> 「`、并`（排除并网）」2/2 仍全是误报、「`、[为是]`（不排除是否）」26 次里 24 次是 `、是否`。

### 1.3 分层

- `check_body_integrity(content) -> BodyIntegrityResult(passed, issues, matched_fragments)`
- `check_title_body_consistency(title, content, expected) -> TitleBodyConsistencyResult`
- `check_editorial_integrity()`
  - 对外**键名不变**（`issues` / `hard_blockers` 仍是**两层合并**），给「整篇稿子」的闸门用；
  - 额外返回 `title_issues` / `body_issues` / `body_integrity` / `title_body_consistency`。
- `TitleAgent.validate_title_compliance` 改用**标题层入口**。

⚠️ **没有用「直接 return True / 降级为 warning / 空 except」这类假修法**：正文层的问题
仍然真实存在、仍然被 `check_editorial_integrity()` 如实报出，只是不再冒充标题的问题。

### 1.4 验收（两个真实选题，`--replay` 复用同一次模型输出，零 LLM）

| 选题 | 正文 | BEFORE 带正文候选通过 | AFTER 通过 | 正文层 |
|---|---|---|---|---|
| 9秒32 机器人打破人类百米纪录 | 1169 字 | **0 / 42** | **31 / 39** | PASS |
| 比亚迪玩跨界？进军人形机器人 | 1534 字 | **0 / 45** | **29 / 39** | PASS |

> ⚠️ 修仪器：`scripts/diagnose_title_stage.py --replay` 原先仍会去挑「最近修改的缓存」，
> 于是可能把 A 选题的正文配 B 选题的候选标题，复算出的「标题与正文不一致」全是**错配**造成的。
> 现在按回放 JSON 里的 `cache_file` 还原同一次运行。

## 2. Blocker 1：Concrete Anchor V2

### 2.1 提取错在哪（逐条都有真实样本）

| 问题 | 旧实现 | 真相 |
|---|---|---|
| 量化值截断 | `18个月`→`18个`、`460万台`→`460万` | 单位表缺 `个月` 与量纲组合，先匹到 `万` 就返回 |
| 真正的公司名提不出来 | 正文里的 `比亚迪`（无后缀）根本不在元素集合里 | 公司通道只认后缀，而 `比亚迪` 没有后缀 |
| 整句话被当公司名 | `进军人形机器人这类公司` | 贪婪匹配 `[…]{2,}(?:公司\|…)` |
| 地名整体不可用 | `二级市`、`市场无法区` | `[..]{2,6}(?:省\|市\|县\|区)` 在 457 篇上命中 **644 次**，其中 `市`+`场` 占 **333 次**（资本市场）；加边界守卫后剩 42 次，约 85% 仍是 `上市`/`节省`/`评论区` 碎片 ⇒ **整条删除** |
| 静默放行 | `if not body_elements: return True` | 既不报错也不留痕，我们不知道闸门有没有生效 |

**净效果（两个真实选题的正文）**：

| 正文 | 旧提取结果 | 新提取结果 |
|---|---|---|
| 9秒32（1169 字） | `{18个}`（1 个，且是截断的） | `{18个月}`（1 个弱锚点 → 闸门 UNAVAILABLE） |
| 比亚迪（1534 字） | 8 个，含 3 个垃圾 + `460万` 截断 | 6 个，高置信度 4 个：`比亚迪`(0.9) `460万台`(0.8) `30%`(0.8) `10万元`(0.8) |

### 2.2 设计

新模块 `src/toutiao_content_factory/services/concrete_anchors.py`（单一真相源；
`TitleAgent.NUMERIC_UNITS` 已删除，避免又出现两份互相矛盾的规则）。

`ConcreteAnchor(text, normalized, kind, confidence, source_span)`，三条高精度通道：

- **company** `0.9`：词典（63 个简称）∪ **固定后缀 + 品牌清洗**
- **quantity** `0.8` / `0.45`：`数字 + 可选数量级(万/亿/千) + 量纲`，**整 token**
- **year** `0.5`：四位年份（19xx/20xx）

公司名后缀通道的清洗（每一条都对应上面量到过的垃圾样本）：

1. 先在正文里**定位后缀**，再向左取 **2–4 字**品牌 —— 不做贪婪匹配；
2. 品牌含虚词字符（`的是这那该其此和与以及或并对为…`）→ 丢；
3. 品牌含虚词**词组**（`如果` / `因为` / `随着` / …）→ 丢；
4. 品牌含行业通名（`半导体` / `大模型` / `机器人` / `明星` / `上市` …）→ 丢；
5. 优先级 = **(左侧是否干净边界, 长度)**。

第 5 条是关键：`如果趋境科技…` 会产出多吞一个字的 `果趋境科技`，而同篇里
`36氪：趋境科技…` 是干净写法。若简单地「谁长留谁」，会把**正确**的 `趋境科技` 删掉、
留下垃圾候选，标题里写 `趋境科技` 反而匹配不上（实测一个 run 影响 12 条候选）。

匹配语义：**整 token 子串匹配**（NFKC + 去空白 + 全角百分号统一 + 大小写）。
`460万台` 不会因为标题只写 `460万` 就算命中 —— 这叫「完整承接」。

### 2.3 三态（不再有静默放行）

| 状态 | 含义 | 闸门行为 |
|---|---|---|
| `PASS` | 命中了高置信度锚点 | 放行 |
| `FAIL` | 正文锚点充足，标题一个都没承接 | **拒绝** |
| `UNAVAILABLE` | 正文锚点不足（< `GATE_MIN_ANCHORS`） | **放行，但必须写 WARNING**（`concrete_hook_unavailable`） |

`GATE_MIN_ANCHORS = 2` 由数据定，不是拍的 —— 见下表分桶。

### 2.4 验收：108 个真实 run 的分桶

| 高置信度锚点数 | run 数 | 零通过 run | 候选通过率 |
|---|---|---|---|
| 0 | 26 | 0（0.0%） | 88.5% |
| 1 | 24 | 0（0.0%） | 90.4% |
| **2–3** | 26 | **10（38.5%）** | 12.1% |
| **4+** | 32 | **19（59.4%）** | 9.1% |

读法：
- 锚点 0–1 的 run 闸门**关着**（记 UNAVAILABLE）；这批 run 的正文本身就提不出
  可承接的具象信息，拿它来判标题有罪是错的。
- 锚点 ≥2 时闸门打开，**每一个 run 里至少有一条候选能承接锚点**（过闸率 ~10%，
  但 20 条候选里挑 2 条足够），**零通过只在真的有 20 条全零阅读模板时出现**。
- 把门槛降到 1 会让零通过率回升到约 40%（多出 24 个 run 打开闸门）；提到 3 则
  会放过锚点恰好 2 个的 run。2 是当前数据下的最优折中。

### 2.5 抽样复核（随机 30 条 FAIL + 15 条 PASS）

- **FAIL 侧**：30 条逐条读过，除下述已知缺口外，**全部是真正的零阅读模板**
  （`人形机器人利润分配，供应链环节分化明显`、`交付效率成为人形机器人定价核心`、
  `AI热起来后，利润先向哪一环转移` …），即标题确实没承接正文里的
  `比亚迪` / `460万台` / `30%` 等事实。**判断正确。**
- **PASS 侧**：15 条逐条读过，**15/15 都真实承接了正文锚点**
  （`三星失手OpenAI…`→`三星`/`OpenAI`；`460万台之后，比亚迪开始重排利润`→`460万台`/`比亚迪`；
  `基流科技之后，科技格局变了`→`基流科技` …）。**没有观察到误放行。**
  （注：`比亚迪16.8%：新能源车项目实测` 这条会过本题的闸，因为它确实带了真数字；
  那是 RULE_007 负责的模板族，不是本闸门的职责。）

### 2.6 已知缺口（如实记录，未修）

在 924 条 FAIL 候选里，检出 **~23 条（2.5%）属于提取缺口导致的假失败**：

| 缺口 | 数量 | 例子 | 原因 |
|---|---|---|---|
| ASCII/能量单位 | 3 | `10GWh之后，锂电开始重排利润` | 单位表没有 `GWh`/`kWh`/`GW`/`MW` |
| 词典里没有、也无后缀的公司简称 | ~20 | `软银核电投资背后…`（`软银`） | 63 条词典未覆盖，且无 `科技`/`公司` 等后缀 |

两者的修法都是**加数据**（单位表、公司词典），而不是改判定逻辑；
本次有意不动，以免把「提取召回」和「闸门语义」两件事混在一起。

## 3. 复现方式（全部零 LLM）

```bash
# 全量回放（108 个真实 run，输出分桶与拒绝原因汇总）
.venv/Scripts/python.exe scripts/replay_title_gate.py --json .runtime/replay_after_b1.json

.venv/Scripts/python.exe scripts/diagnose_title_stage.py --replay .runtime/title_stage_diagnose_by.json
```

**为什么必须用 `--replay`**：两次独立生成会得到不同的候选，
你无法判断差异是「闸门变了」还是「模型这次说了别的」。

## 4. 剩余阻塞与「是否可以进 D2」

**剩余阻塞（都不属于 Blocker 1/2）**：

1. **候选池本身太像**：`missing_concrete_hook` 现在的 979 条拒绝里，主体是
   20 条候选里十几条同一族模板（`X之后，Y开始重排利润` 等）。闸门没错，
   是**候选生成**的问题 ⇒ D1 / 提示词侧。
2. **46.3% 的 run 闸门 UNAVAILABLE**：根因是**正文太薄**（提不出 ≥2 个高置信度锚点）。
   这是**写手侧**问题，已用 WARNING 显式留痕，但还没有上游动作（换选题 / 重写正文）。
3. **提取缺口 ~2.5%**：见 2.6。
4. **`title_body_inconsistency` 的语义边界**：当正文没覆盖选题主体时（如选题叫「比亚迪…」
   而正文通篇不提比亚迪），现在会判**标题**不一致。更准的归属应该是**正文**没覆盖选题。
   本次未动（属于 D3/更深的层）。

**是否可以进入 D2？** — **可以，但 D2 的收益已被本次修为大幅削弱。**
D2 要解决的问题是「合规闸全灭时静默跳过、等于未生效」。本次实测：修完后
`9秒32` 选题 39 条候选过闸 31 条、`比亚迪` 选题 39 条过闸 29 条，
**合规闸全灭不再是常态**（旧实现是这两个选题都 0/42、0/45）。
所以 D2 现在更接近一个**防御性**改动（确保极端情况下「全灭」不被静默吞掉），
而不是解决当前 26.9% 零通过的主因。**建议先做 D1（候选池隔离）与正文侧，
再回来做 D2。**
